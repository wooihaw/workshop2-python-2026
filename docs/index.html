01

Readings and collections

Section 110 minuteswork in pairs syntax · built-in types · sequences

Your task

sensor_readings.py — start from this

readings = [21.5, 23.0, 19.8, 25.1, 22.4]
labels   = ("node-a", "node-b", "node-c")
  1. Print the type of each variable.
  2. Report the first, last and middle reading.
  3. Build a list of the readings above 22.0.
  4. Format a one-line summary with an f-string — for example node-a: 5 readings, mean 22.36.
  5. Explain why labels cannot be appended to.
Check as you go Try each step in the REPL on its own before you write the full script.

Hints

  • type(x) tells you what you are actually holding.
  • Negative indices count from the end — readings[-1].
  • len(seq) // 2 lands on the middle item.
  • A comprehension has the shape [expr for item in seq if condition].
  • f"{value:.2f}" rounds inside the string.
  • A tuple cannot be changed once it is created.

Attempt all five steps first. Step 5 is the one worth arguing about.

Worked solution

# sensor_readings.py
readings = [21.5, 23.0, 19.8, 25.1, 22.4]
labels   = ("node-a", "node-b", "node-c")

# 1. what am I holding?
print(type(readings), type(labels))
# <class 'list'> <class 'tuple'>

# 2. first, last, middle
first, last = readings[0], readings[-1]
middle = readings[len(readings) // 2]
print(first, last, middle)          # 21.5 22.4 19.8

# 3. filter in a single pass
hot = [r for r in readings if r > 22.0]
print(hot)                          # [23.0, 25.1, 22.4]

# 4. derive the mean, format it where it is used
mean = sum(readings) / len(readings)
print(f"{labels[0]}: {len(readings)} readings, mean {mean:.2f}")
# node-a: 5 readings, mean 22.36

# 5. labels is a tuple - immutable by design.
#    labels.append("node-d") raises AttributeError.

Why it works

  • type() confirms list versus tuple before you rely on either.
  • readings[-1] beats readings[len(readings) - 1].
  • The comprehension filters in one pass — no accumulator, no counter.
  • mean is derived on demand, never stored alongside the data it summarises.
  • The f-string keeps the formatting next to the value it describes.
  • labels stays a tuple, so the node names cannot be changed by accident.
Common slip Reaching for readings[6] and hitting IndexError. Five items means valid indices 0–4, or −1 to −5 from the end.
02

Branching, loops and functions

Section 215 minutes control flow · functions · modules

Your task

grading.py — start from this

scores = [0.91, 0.47, 0.78, 0.55, 0.96]
  1. Write grade(score) returning "high", "mid" or "low" using if / elif / else.
  2. Give it threshold arguments with sensible defaults.
  3. Loop with enumerate and print the index, score and grade for every entry.
  4. Stop early once a score above 0.95 is found, and report which index it was.
  5. Save it as grading.py and import it from another file.
Constraint Keep grade() free of print statements. A function that prints cannot be tested.

Hints

  • if / elif / else stops at the first match — order the branches accordingly.
  • def f(x, high=0.9) sets a default value.
  • enumerate(seq) yields the index and the value together.
  • break leaves the loop immediately.
  • Return a value; do not print inside the function.
  • Guard the loop with if __name__ == "__main__": so importing the module stays quiet.

Prove step 5 by importing grade() from a second file — that is the whole point of the exercise.

Worked solution

# grading.py
def grade(score, high=0.90, mid=0.60):
    """Bucket a score into three bands."""
    if score >= high:
        return "high"
    elif score >= mid:
        return "mid"
    return "low"


if __name__ == "__main__":
    scores = [0.91, 0.47, 0.78, 0.55, 0.96]
    for i, s in enumerate(scores):
        print(i, s, grade(s))
        if s > 0.95:
            print(f"early stop at index {i}")
            break

# 0 0.91 high
# 1 0.47 low
# 2 0.78 mid
# 3 0.55 low
# 4 0.96 high
# early stop at index 4

…and from any other file in the project

from grading import grade

grade(0.83)                 # 'mid'
grade(0.83, mid=0.90)       # 'low'  - thresholds are arguments

Why it works

  • Defaults let callers ignore the thresholds until the day they need to change them.
  • Early returns keep the branches flat — no nesting, no else tail.
  • enumerate avoids range(len(scores)) and the indexing that comes with it.
  • break stops the scan the moment the goal is met — no wasted iterations.
  • The function returns instead of printing, so it can be imported, reused and tested.
  • The __main__ guard means importing grading does not run the demo loop.
Common slip Printing inside the function instead of returning. It looks identical in the terminal and is useless everywhere else.
03

Robust file processing

Section 320 minutes exceptions · file I/Odata/readings.csv

Your task

data/readings.csv — 60 rows, and not all of them are clean

ts,node,temp_c,hum
2026-03-05 08:00:00,node-a,20.22,65.7
2026-03-05 09:20:00,node-b,,69.2
2026-03-05 11:00:00,node-a,n/a,54.6
2026-03-05 21:20:00,node-b,"21,5",64.0
2026-03-06 02:20:00,node-b,23.4C,73.3
  1. Open it inside a with block, encoded utf-8.
  2. Convert each temp_c value to float.
  3. Catch ValueError and count the bad rows instead of letting the script crash.
  4. Write the clean values out to clean.json.
  5. Raise a clear error if the file is missing — do not fail silently.
  6. Print how many rows you had to skip.
Your answer should be 51 values kept, 9 rows skipped. Then corrupt a row on purpose and confirm the script still survives.

Hints

  • with open(...) closes the file for you, even on an exception.
  • csv.DictReader gives you dict-like rows keyed by the header.
  • float("") raises ValueError — so do "n/a", "--" and "23.4C".
  • Wrap only the risky line in try, never the whole loop body.
  • Path.exists() checks before you read.
  • json.dump writes the list back out.

The nine broken values are all different on purpose: blanks, sentinels, a decimal comma and a stray unit.

Worked solution

# clean_readings.py
import csv
import json
from pathlib import Path

path = Path("data/readings.csv")
if not path.exists():
    raise FileNotFoundError(f"missing: {path}")

clean, bad = [], 0
with open(path, encoding="utf-8") as f:
    for row in csv.DictReader(f):
        try:
            clean.append(float(row["temp_c"]))
        except ValueError:
            bad += 1

with open("clean.json", "w", encoding="utf-8") as f:
    json.dump(clean, f, indent=2)

print(f"kept {len(clean)} values, skipped {bad} bad rows")
# kept 51 values, skipped 9 bad rows

Why it works

  • The guard fails fast with a message that names the path it could not find.
  • try wraps one line only, so a typo elsewhere still raises instead of being counted as bad data.
  • Bad rows are counted, not silently lost — you can report the data quality afterwards.
  • with closes the file even when an exception is raised.
  • An explicit encoding="utf-8" makes the script behave the same on WSL2 and on Windows.
  • Watch the edge case: float("nan") does not raise — it returns a float. Only genuinely unparseable text is caught here.
Common slip A bare except: that swallows your own typos and reports them as bad data. Name the exception you can recover from and re-raise the rest.
04

An end-to-end mini workflow

Section 425 minutes pandas · matplotlib · scikit-learn rehearsal for the closing lab

Your task

Use the built-in digits dataset — no download needed

from sklearn.datasets import load_digits

d = load_digits(as_frame=True)
  1. Load it into a pandas DataFrame.
  2. Print the shape and the class counts.
  3. Show one digit with plt.imshow().
  4. Split 80/20, stratified, with a fixed seed.
  5. Fit a RandomForestClassifier and report accuracy on the held-out test set.
  6. Bonus: print a confusion matrix and see which digits get mixed up.
Expected result A shape of (1797, 65) and test accuracy around 0.97.

Hints

  • load_digits(as_frame=True) returns pandas objects directly.
  • 64 columns = one 8×8 grayscale image, flattened. The 65th is the target.
  • value_counts() checks the class balance.
  • imshow(d.images[0], cmap="gray") plots the unflattened image.
  • stratify= keeps all ten digits proportional in both splits.
  • model.score() returns accuracy directly.

Once it runs, swap in a different classifier and compare the score — the surrounding four steps do not change.

Worked solution

import matplotlib.pyplot as plt
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import ConfusionMatrixDisplay

# 1-2. explore before you model
d = load_digits(as_frame=True)
df = d.frame
print(df.shape)                     # (1797, 65)
print(df["target"].value_counts())

# 3. one sample, as the 8x8 image it really is
plt.imshow(d.images[0], cmap="gray")
plt.title(f"label: {d.target[0]}")
plt.show()

# 4. hold the test set out BEFORE fitting anything
X_train, X_test, y_train, y_test = train_test_split(
    d.data, d.target, test_size=0.2,
    stratify=d.target, random_state=42)

# 5. fit, then score on data the model has never seen
model = RandomForestClassifier(n_estimators=200, random_state=42)
model.fit(X_train, y_train)
print(f"accuracy: {model.score(X_test, y_test):.3f}")   # around 0.97

# 6. bonus - which digits get mistaken for which?
ConfusionMatrixDisplay.from_estimator(model, X_test, y_test, cmap="Blues")
plt.show()

Why it works

  • Shape and class counts catch bad data early, before you spend a training run on it.
  • Each row is one flattened 8×8 image — 64 pixel columns plus the target.
  • stratify=d.target keeps all ten classes evenly represented in both splits.
  • The test set is held out before anything is fitted, so the score means something.
  • score() is accuracy; the confusion matrix shows which digits get confused — 4 with 9, 3 with 8.
  • random_state=42 fixes both the split and the forest, so your neighbour gets the same number.
  • The same four beats every time: split, fit, predict, evaluate.
Common slip Fitting on all the data and then reporting test accuracy. The number will look excellent and mean nothing.
