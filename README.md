## Setup

`uv` is already installed from Workshop 1.

```bash
uv init workshop2 && cd workshop2
uv python pin 3.13

uv add numpy pandas matplotlib scikit-learn
uv add joblib jupyterlab
uv add torch                 # large download, CPU wheel
uv add tensorflow            # large download

uv run python -c "import numpy, pandas, sklearn"
uv run jupyter lab           # or open the folder in VS Code
```

**Do the two large downloads before the session** — `torch` and `tensorflow` together are
several gigabytes and will not finish over a room full of shared Wi-Fi.

Commit `uv.lock`. It pins exact versions so every participant runs the same stack and gets
the same numbers.

### GPU (optional)

Neither notebook needs a GPU; both run on CPU in a few minutes. If you want one:

| Framework | Command |
|---|---|
| TensorFlow | `uv pip install "tensorflow[and-cuda]"` — Linux or WSL2 only, native Windows support stopped at TF 2.10 |
| PyTorch | `uv pip install torch torchvision --torch-backend=auto` |

Verify with `tf.config.list_physical_devices('GPU')` or `torch.cuda.is_available()`. An
empty list means the driver, the WSL2 setup or the CUDA extra is missing — not your code.

## The datasets

Both files are synthetic, generated by `tools/make_datasets.py` with a fixed seed, so they
are safe to redistribute and identical for every participant.

### `data/sensors.csv`

Simulated environmental readings from six sensor nodes, 15-minute intervals, 2–4 March 2026.

| Column | Type | Notes |
|---|---|---|
| `ts` | timestamp | `YYYY-MM-DD HH:MM:SS`, parse with `pd.to_datetime` |
| `node` | string | `node-a` … `node-f`, **deliberately untidy** — mixed case and stray spaces |
| `temp_c` | float | temperature in °C, **48 values missing** |
| `hum` | float | relative humidity %, **73 values missing** |
| `t_max` | float | that node's daily maximum |
| `t_min` | float | that node's daily minimum |
| `fault` | int | 0 / 1 target for the classification lab |

Shape and quality, by design:

| | |
|---|---|
| Rows as written | 1488 |
| Non-null `temp_c` | **1440** |
| Exact duplicate rows | 48 |
| Distinct `node` strings before cleaning | 24 |
| Distinct `node` strings after `.str.strip().str.lower()` | 6 |
| `fault` positive rate | ≈ 25 % |
| Clean rows after `drop_duplicates()` + `dropna(subset=["temp_c"])` | 1392 |

Every teaching move in the deck has something real to bite on: `isna().sum()` finds gaps,
`drop_duplicates()` removes 48 rows, `groupby("node")` returns 24 groups until you clean
the strings, `pivot_table(index="ts", columns="node", values="temp_c")` gives a tidy
240 × 6 table, and `t_max - t_min` is a genuine engineered feature rather than a constant.

The numbers on the *"A tour of the JupyterLab window"* slide reproduce exactly:

```python
import pandas as pd
df = pd.read_csv("data/sensors.csv")
df["temp_f"] = df["temp_c"] * 9 / 5 + 32
df["temp_f"].describe()
# count 1440   mean 70.4   min 61.2   max 79.8
```

The `fault` target is learnable but not trivial — a `RandomForestClassifier` on
`temp_c`, `hum`, `temp_range`, `hour` and one-hot `node` reaches about **0.92** accuracy
against a **0.74** majority-class baseline. Students see a real lift instead of either a
suspicious 1.00 or noise.

### `data/readings.csv`

A small file (60 rows: `ts`, `node`, `temp_c`, `hum`) for **Exercise 3: robust file
processing**. Nine `temp_c` values are unparseable, each a different failure mode you meet
in real logging output:

```
""      "n/a"    "N/A"    "--"    "ERROR"    "21,5"    "   "    "null"    "23.4C"
```

Every one of them raises `ValueError` from `float()` — none of them raise `TypeError` or
sneak through as a silent `nan` — so the exercise's `except ValueError` catches exactly the
nine it should. `"21,5"` is a European decimal comma and is properly quoted in the CSV, so
`csv.DictReader` still returns four fields.

A correct solution prints **51 clean values and 9 skipped rows**. That is the checkable
answer to grade against.

## Workshop structure

| Section | Topic | Checkpoint |
|---|---|---|
| 1 | Syntax, built-in types, collections and dictionaries | Exercise 1 — readings and collections (10 min) |
| 2 | Conditional branching, iteration, functions and modules | Exercise 2 — branching, loops and functions (15 min) |
| 3 | Exception management, tracebacks, file I/O | Exercise 3 — robust file processing, uses `readings.csv` (20 min) |
| 4 | NumPy, pandas, matplotlib, scikit-learn, Keras, PyTorch | Exercise 4 — end-to-end mini workflow (25 min) |

Exercises 1, 2 and 4 are self-contained — the data is written into the slide. Only
Exercise 3 and the closing lab read from `data/`.

### Closing lab

Load → Clean → Explore → Model → Extend, on `data/sensors.csv`:

1. **Load** — read the CSV with pandas and inspect its structure.
2. **Clean** — handle the missing values and tidy the node labels, then engineer two new
   features (`temp_range = t_max - t_min` and `hour = ts.dt.hour` are the obvious pair).
3. **Explore** — plot distributions and a correlation view with matplotlib.
4. **Model** — split, fit and evaluate a scikit-learn classifier on `fault`.
5. **Extend** — rebuild the same model in Keras or PyTorch and compare.

## Exercise page

`docs/index.html` is a self-contained page holding all four exercises — the task, the hints,
and a worked solution behind a **Show solution** button so students attempt the problem
before they read the answer. A *Reveal all* control in the toolbar lets you open everything
at once when you walk through the answers together.

It is one file with no build step and no local dependencies, so publishing it takes one
setting:

> **Settings → Pages → Build and deployment → Source: Deploy from a branch**, then pick
> your default branch and the **`/docs`** folder.

The page is then live at `https://<your-username>.github.io/<repo>/`. Give students that
link at the start of the session rather than the repository URL — it is the only thing they
need open beside their editor.

Two details worth knowing if you edit it:

- Syntax highlighting loads from a CDN. If it fails, the code still renders as plain
  monospace text — the page never depends on it.
- It follows the reader's light or dark system theme.

## Notebooks

Both notebooks classify MNIST handwritten digits, so the same problem is solved twice and
the two approaches can be compared directly.

| Notebook | Approach | Model |
|---|---|---|
| `ml_mnist.ipynb` | Classical ML with scikit-learn | `StandardScaler` → `MLPClassifier(128, 64)`, 30 iterations |
| `dl_mnist.ipynb` | Deep learning with TensorFlow/Keras | LeNet-5 style CNN, early stopping on validation loss |

Both end with a classification report and a confusion matrix, which is the point of the
pairing — accuracy alone hides *which* digits get mistaken for which.

Cells marked `# To do:` are the ones to work through with participants. The MNIST data
downloads through `keras.datasets` on first run (~11 MB), so **run one cell before the
session** if the venue's network is unreliable.

## Regenerating the data

```bash
python tools/make_datasets.py
```

Standard library only — no pandas, no NumPy — so it runs in any Python 3.9+ interpreter,
including before the workshop environment exists. The seed is fixed, so the output is
byte-identical every time. Change the seed if you want a fresh cohort dataset; the
distribution shaping keeps `temp_f` on `count 1440, mean 70.4, min 61.2, max 79.8` only
for the seed as shipped, so re-check the JupyterLab slide if you do.

## Notes on names

Three small things worth aligning between the deck and this repository:

- The file is **`sensors.csv`** (plural), matching every reference in the slides.
- The humidity column is **`hum`** throughout. One slide (*Tabular data with pandas*)
  writes `df[["temp_c", "humidity"]]`; that should read `hum` to match the file.
- *Solution 3* uses `Path("readings.csv")`. Both datasets live in `data/`, so the working
  line is `Path("data/readings.csv")` — or run the exercise from inside `data/`.
